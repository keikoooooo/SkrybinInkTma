# Руководство по хранению изображений

## Текущая ситуация

Сейчас в приложении изображения хранятся как URL-строки в базе данных:
- `users.photo_url` - фото пользователей из Telegram
- `artists.avatar_url` - аватары мастеров
- `works.image_url` - фото работ (портфолио)

## Варианты хранения

### 1. 🚀 Облачное хранилище (рекомендуется для продакшена)

#### Вариант A: Cloudinary (бесплатный тариф до 25GB)
**Плюсы:**
- Автоматическая оптимизация и ресайз
- CDN встроен
- Бесплатный тариф: 25GB хранилища, 25GB трафика/месяц
- Простая интеграция

**Настройка:**
```bash
# Установите библиотеку
go get github.com/cloudinary/cloudinary-go/v2
```

#### Вариант B: AWS S3 + CloudFront
**Плюсы:**
- Масштабируемость
- Низкая стоимость
- Высокая надежность

**Минусы:**
- Требует настройки AWS аккаунта
- Более сложная настройка

#### Вариант C: ImgBB (простой вариант)
**Плюсы:**
- Очень простая интеграция
- Бесплатный API
- Не требует регистрации для базового использования

**Минусы:**
- Ограничения по размеру файла (32MB)
- Нет автоматической оптимизации

### 2. 💾 Локальное хранение (для разработки)

**Плюсы:**
- Простота настройки
- Не требует внешних сервисов
- Бесплатно

**Минусы:**
- Не масштабируется
- Нужен веб-сервер для раздачи файлов
- Проблемы при деплое на Railway/Render

### 3. 📱 Telegram Bot API (альтернатива)

Можно использовать Telegram Bot для хранения изображений через бота, но это не рекомендуется для продакшена.

## Рекомендуемое решение: Cloudinary

### Шаг 1: Регистрация

1. Зарегистрируйтесь на [cloudinary.com](https://cloudinary.com)
2. Получите:
   - Cloud Name
   - API Key
   - API Secret

### Шаг 2: Установка зависимостей

```bash
cd server-go
go get github.com/cloudinary/cloudinary-go/v2
go get github.com/cloudinary/cloudinary-go/v2/api/uploader
```

### Шаг 3: Добавьте в `.env`

```env
CLOUDINARY_CLOUD_NAME=your_cloud_name
CLOUDINARY_API_KEY=your_api_key
CLOUDINARY_API_SECRET=your_api_secret
```

### Шаг 4: Использование

См. файл `server-go/internal/utils/cloudinary.go` (будет создан)

---

## Альтернатива: Локальное хранение (для разработки)

Если вы хотите начать с локального хранения для тестирования:

### Настройка локального хранилища

1. Создайте папку для изображений:
```bash
mkdir -p server-go/uploads/images
```

2. Добавьте в `.env`:
```env
UPLOAD_DIR=./uploads
PUBLIC_URL=http://localhost:8080
```

3. Настройте статическую раздачу файлов в `main.go`

---

## Структура папок для локального хранения

```
server-go/
├── uploads/
│   ├── images/
│   │   ├── works/          # Фото работ
│   │   ├── artists/        # Аватары мастеров
│   │   └── users/          # Фото пользователей (если нужно)
│   └── temp/               # Временные файлы
```

## API для загрузки изображений

После настройки хранилища будет доступен эндпоинт:

```
POST /api/upload/image
Content-Type: multipart/form-data

Параметры:
- file: файл изображения
- type: тип (work|artist|user)
- [optional] resize: размер (small|medium|large)

Ответ:
{
  "ok": true,
  "url": "https://res.cloudinary.com/.../image.jpg",
  "public_id": "works/123456"
}
```

## Рекомендации

### Для разработки:
- Используйте локальное хранение или ImgBB

### Для продакшена:
- Cloudinary (лучший баланс цена/качество)
- AWS S3 + CloudFront (если нужен полный контроль)

### Оптимизация изображений:
- Всегда ресайзьте изображения перед сохранением
- Используйте WebP формат для лучшего сжатия
- Ограничьте максимальный размер файла (например, 5MB)

---

## Безопасность

1. **Валидация файлов:**
   - Проверяйте MIME-тип
   - Ограничивайте размер файла
   - Проверяйте расширение

2. **Ограничение доступа:**
   - Только авторизованные пользователи могут загружать
   - Админы могут загружать работы и аватары
   - Пользователи могут загружать только свои фото

3. **Санитизация имен файлов:**
   - Удаляйте опасные символы
   - Используйте UUID для имен файлов
